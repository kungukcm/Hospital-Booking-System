# FINAL SUBMISSION SUPPLEMENT. SUBMISSION LOGIC, REFERENCING, AND DOCUMENT COMPLETION

This supplement is intended to support final submission by explaining how the manuscript package should be completed and checked before it is handed in. The thesis is now organized as a comprehensive draft body with front matter, chapter sections, supplements, and reference-support files. The remaining task is not to create a new intellectual argument, but to bring the package to submission quality by ensuring that the document is internally consistent, properly formatted, and referenced with care.

The first submission concern is reference integrity. The project folder contains many useful source documents, but not all of them expose bibliographic metadata in a clean way. That means the reference list should not pretend to be more exact than the source extraction allows. A responsible thesis should distinguish between references that have been fully verified and those that are still draft placeholders. This is why the package now includes both a bibliography draft and a reference verification status note. Together they make clear what has been confirmed and what still needs manual inspection.

The second submission concern is document coherence. When a thesis grows through many expansion layers, it can become repetitive or structurally uneven. That is acceptable during drafting, but the final submission should remove obvious redundancy, keep headings consistent, and avoid mixing chapter-level arguments with appendix-style notes in the middle of a main chapter. The merged master manuscript is intended to support this cleanup by giving a single source from which a final Word version can be reviewed and refined.

The third submission concern is format alignment with the institutional template. The thesis format file provided in the project folder clearly specifies the arrangement of cover pages, title pages, submission sentences, approval text, abstract, contents, and body layout. The final document should mirror that structure as closely as possible. Page numbering, heading hierarchy, and front-matter order matter because they are part of the submission requirements, not optional design choices. Even a strong thesis can be delayed if the front matter does not match the required format.

The fourth submission concern is language and tone. Since the project concerns AI for a Kenyan hospital context and includes Swahili support, the final document should maintain academic English in the thesis narrative while documenting Swahili support as an implemented feature. It is important not to overmix styles in a way that makes the manuscript look informal. The argument can acknowledge bilingual support while still keeping the thesis itself readable, formal, and consistent.

The fifth submission concern is final file hygiene. For submission, the author should keep a clear distinction between working files and final deliverables. The thesis package now includes many supporting supplements and reference guides, which is helpful during drafting, but the final Word submission should ideally be one clean manuscript with appendices and bibliography in the correct order. The extra files should remain available in the workspace for traceability, but they should not clutter the final submitted document unless the department explicitly wants them included.

The most practical final workflow is straightforward. The merged master manuscript should be reviewed one last time for obvious duplication, the reference list should be finalized from the source documents, and the Word document should be regenerated if any major structural changes are made. After that, the final document can be saved as the submission copy. This is the simplest way to keep the thesis academically honest while making it submission-ready.

The overall conclusion of this supplement is that the thesis package has reached a stage where content generation can shift into submission preparation. The focus should now be on cleanup, validation, formatting, and reference accuracy rather than further expansion alone. That is the correct transition point for a document of this type.
